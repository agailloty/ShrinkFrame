# Agent operating guide

This file is the entry point for every implementation agent working on ShrinkFrame.

## Mandatory reading order

1. `README.md`
2. `docs/00-product-brief.md`
3. `docs/01-architecture.md`
4. `docs/02-domain-and-state.md`
5. `docs/03-workflows.md`
6. The topic document relevant to the current task
7. `docs/decisions.md`
8. The assigned file in `prompts/`

Do not load the entire prompt directory. Read `prompts/README.md`, the assigned prompt, and only its declared prerequisites.

## Non-negotiable rules

- Target a stable .NET 10 SDK. Do not pin to a preview SDK.
- Preserve the modular-monolith dependency direction documented in `docs/01-architecture.md`.
- Do not expose an Immich API key to browser code, HTML, URLs, logs, exceptions, or API responses.
- Stream large files. Never buffer an entire video in memory.
- Never invoke FFmpeg through a shell or a single concatenated argument string. Use `ProcessStartInfo.ArgumentList`.
- Do not delete or trash original Immich assets.
- Do not publish `NotBeneficial` results without explicit user confirmation.
- Treat loss of capture date or effective rotation as a blocking validation error.
- Keep SQLite as the source of truth for job ownership and state transitions.
- Keep binary artifacts out of the database.
- All filesystem paths must be generated by the server and constrained below the configured work root.
- Add no user authentication in the POC.
- Use English for code, UI text, logs, and documentation added to this directory. Prepare UI strings for later localization.

## Completion discipline

Each prompt is a separate milestone. Before completing one:

- satisfy every acceptance criterion;
- run the listed build and test commands;
- update documentation when implementation decisions differ from assumptions;
- add a concise entry to `docs/implementation-log.md`;
- do not implement later prompts unless needed for compilation and explicitly documented.

If an endpoint or framework behavior has changed, consult the current official documentation and record the verified version/date. Do not guess API contracts.
